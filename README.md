## 数据口径（重要）

- **每日涨跌**：场内收盘价相对前一交易日收盘价。不是相对1元发行价；“上市以来”相对本站记录的首个交易日（2026-11-23）收盘价。
- **基金份额**：总份额（亿份）及相对上一份份额记录的增减。**份额增是申购、减是赎回，是资金进出的直接口径**，
  与 PCF 持仓变动互补。上交所按日归档（当日数据一般收盘后才出，查不到就往前找最近 5 天）；
  深交所只提供当前快照（T 日晚为预估值、T+1 早为确认值）。两所份额的日期可能比行情晚一天，以份额自身日期为准。
- **持仓**：来自交易所每日 PCF（申购赎回清单），每个交易日开市前披露、基于前一交易日日终组合。
  **PCF 是申赎篮子估算，不等同基金精确持仓**；完整持仓以季报/半年报/年报为准。不要拿 PCF 单只权重直接“抄作业”。
- **PCF 权重**：上交所 = 现金替代金额 / 每申购赎回单位净值；深交所 = 成分股份数 × 成分股现价 / 每单位净值（股价拉不到时权重留空，只保留份数）。

## 数据源

全部免费、无需 key，抓取脚本按顺序兜底，全部失败时以非零退出、让 Action 变红，不静默写假数据：

- 行情：东方财富 push2 → 腾讯 `qt.gtimg.cn` → 新浪 `hq.sinajs.cn` → Yahoo Finance
- PCF：上交所 `query.sse.com.cn/commonQuery.do`（sqlId `COMMON_SSE_CP_JJLB_ETFJJGK_GGSGSHQD_JBXX_C` / `..._COMPONENT_C`）；
  深交所 `www.szse.cn/api/report/ShowReport/data`（CATALOGID=`sgshqd`）+ `reportdocs.static.szse.cn` 的 XML。
  PCF 的接口形态参考了 [Jimmy-asks-AI/a-share-etf-pcf-metrics](https://github.com/Jimmy-asks-AI/a-share-etf-pcf-metrics)（MIT）。
- 份额：上交所 `query.sse.com.cn/commonQuery.do`（sqlId `COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L`，`STAT_DATE` 按日归档，`TOT_VOL` 单位万份）；
  深交所 `fund.szse.cn/api/report/ShowReport/data`（CATALOGID=`1000_lf`，`selectJjlb=ETF`，当前快照，`dqgm` 单位万份）。
  端点形态参考了 [simonlin1212/a-stock-data](https://github.com/simonlin1212/a-stock-data) §4.7 `etf_shares()`（Apache-2.0）。

已验证（2026-11-24 本机实测）：`npm run fetch` 全程约 45 秒，18 只行情 + 18 只 PCF 全部成功。
行情走了新浪兜底（东财 push2 在本机返回 502、腾讯超时；GitHub Runner 上东财通常可达）。
深交所 PCF 走 `reportdocs.static.szse.cn/files/text/etf/ETF<code><日期>.txt`（GBK 文本），上交所走 `query.sse.com.cn`。
Yahoo 对这批新 ETF 暂无数据，只作最后兜底。节假日用东财 K 线判断“今天不是交易日”，只更新 `latest.json`，不往历史里追加。

## 部署到 GitHub

1. 新建公开仓库，名字建议就叫 `active-etf-tracker`，把本目录推上去。
2. 仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。
3. `astro.config.mjs` 里的 `site` / `base` 按你的仓库改：
   - 仓库名是 `active-etf-tracker`：不用改，`site: https://<用户名>.github.io/active-etf-tracker/`，`base: '/active-etf-tracker/'`。
   - 其它仓库名：把两处都改成对应名字；如果是用户站（`<用户名>.github.io`），`base` 改成 `'/'`。
4. Actions 页点 **Daily active ETF data + deploy** → Run workflow 手动跑一次，确认数据和页面都出来。
5. 之后每天北京时间16:00（UTC 08:00，周一至周五）自动跑：拉数据 → 提交 `public/data/` → 构建 → 部署 Pages。

### 部署的两个坑（别踩第二遍）
- **build 与 deploy 必须分两个 job**（deploy 用 `needs: build`）。`actions/deploy-pages` 会在 upload 完 200–300 毫秒后就去查产物列表，接口有最终一致性延迟，偶尔查到 0 个产物就报错（[actions/deploy-pages#451](https://github.com/actions/deploy-pages/issues/451)）。同 job 布局时这个失败是随机的，报错里“去看 githubstatus”是 catch 块的固定文案，不是真有事故。
- **失败了不要点 Re-run failed jobs**：重跑会在同一次运行里再传一份同名产物，触发 “Multiple artifacts” 错误。正确做法是修好问题再推一个新 commit，让新运行去部署。
- **`.github/workflows/daily.yml` 不能经由 Muse 的 GitHub 连接器推送**：Meta Muse GitHub App 没有 Workflows 权限，含 workflow 文件的推送会 403。workflow 文件的改动一律在 GitHub 网页端提交；其余文件走连接器 snapshot-push 流程，manifest 只列实际改动的文件。

## 长赢持仓评价（A/B/C）

总榜“长赢评价”列（徽章 + 一句话简评），基金详情页有详细评价正文（六条线读数在正文里）。
按且慢长赢方法评价 18 只基金的持仓（持仓为 2026-11-24 PCF Top20 快照），**是持仓评价，不是投资建议**。

- **方法**：且慢长赢 skill（`~/workspace/custom-skills/qieman_*`，源自且慢「ETF拯救世界」645 篇文章）+ qieman-finance《核心思想综合报告.md》第 2、3、5、6 节。估值是温度计不是择时器；高估值 + 拥挤要保本金、分散、等待；风险识别优先于精确预测；分红要看真实盈利、持续分红、ROE、周期位置，不能只看股息率。
- **口径（先定后评，不许事后调）**：六条线，每条先给读数（优/中/差）再综合定级，完整口径见 [`fund-grades-rubric.md`](fund-grades-rubric.md)：
  1. **估值**：Top20 加权 PE(TTM)/PB/股息率 + turtle 价格条件通过率（通过的持仓权重 ÷ 全部已分析持仓权重；已分析权重占基金净值不足 10% 时该指标不可用，改用 PE/PB 为主）。优 = 加权 PE ≤25 或通过占比 ≥50%；差 = 加权 PE >45 或 PB >4 或通过占比 <20%。
  2. **拥挤度**：Top20 中被 ≥3 只基金重叠持有的股票权重占比（分母统一为 **Top20 内占比**）+ 单一热门赛道占比。差 = 重叠 >30% 或单一热门赛道 >50%。
  3. **风险**：高估值 + 拥挤同时成立即重点防范；看估值与质量能否兜底（turtle 经营基准）。
  4. **质量/分红**：turtle 经营基准分布；红利风格重持续分红、ROE、周期位置；银行/保险看 ROE、分红、资产质量。
  5. **分散度**：Top20 合计权重、第一大持仓、第一大行业权重。差 = Top20 >70% 或单一行业 >50% 或单只 >8%。
  6. **仓位**：最新已披露的股票仓位（季报披露优先，无新披露沿用上月并注明），结合估值判断。差 = 估值偏高且仓位 >70%，或估值合理但仓位 <30%。
  - **综合**：A（优秀）= 总体占优，至多一条“中”，无“差”；B（一般）= 有得有失；C（差）= 高估值 + 拥挤同时成立，或质量/分散有明显短板。
- **结果（2026-11-25，名单扩至 62 只后重评）**：A 1 只（581090 华泰柏瑞价值精选，PE 仅 8 倍、零热门赛道）、B 12 只、C 5 只（158906 华宝、158909 建信、581000 摩根、581060 永赢，均为高估值 + 拥挤；新增 581020 华安均衡慧选——PB 4.04 且 turtle 通过率 0%，触发高估值 + 拥挤）。首版（2026-11-24，35 只时）为 A1/B13/C4，唯一变化是 581020 由 B 降至 C。
- **数据缺口（复核时先看这里）**：股息率、ROE 基本未核实（东财 push2 接口无可信字段），红利基金的分红成色结论置信度最低；6 只上交所基金的 PCF 快照 Top20 本来就不满 20 只（581020 仅 12 只、581050 仅 8 只等），其分散度/拥挤度结论封顶为“中”；581060 的 C 依赖截断快照，待快照补齐后复核；turtle 价格条件通过率不可用的基金只剩 581080 一只（已分析权重 9.73% <10%）；Top20 之外持仓未知。

## 每月重评（龟龟 + 长赢）

龟龟分析与长赢评价每月重跑一次，保持结论不过期：

- **时间**：每月 1 号上午约 09:11（北京时间），首跑 2026-12-01。定时任务 `monthly-turtle-rerun`（Muse cron，任务名“龟龟策略 + 长赢评价月度重跑”）。
- **截止日**：上月最后一个交易日；所有分析里的“现价”都用该日收盘价，财报用截至该日已披露的最新年报/季报。
- **取数**：先跑 `python3 scripts/fetch-turtle-data.py`（62 只，约 15 分钟；数据源是 a-stock-data §6.4 新浪三表 + §6.3 东财个股信息 + §4.4 分红），产出 `turtle-data/<代码>.json` + `summary.csv`：每只 15 个年末期（2011–2025 起）的 OCF / Capex / 现金 / 有息负债 / 归母权益、机械 M5 / A3 / F_norm / TTM 的 L / F0、最新季末资产负债表 `latest_bs`（K 按方法口径用最新季末数算）、历年分红。**脚本只预填机械数，分析员仍要核对年报 + 做经营判断**（可比年份筛选、非经常影响、H 股募资剔除、受限现金等）；交叉核对过：格力 TTM OCF 247.18 亿 / Capex 14.91 亿与手算报告完全一致，中际旭创最新季末 K 513.81 亿 vs 报告 512.6 亿。`turtle-data/` 是本地工作底稿，不上站、不推送。
- **龟龟**：按 V5.2.2 重做名单内每只股票的完整分析；名单按最新 PCF Top20 重算（被 3 只以上基金持有、或是任意一只基金的 Top3），已有的 62 只即使掉出名单也保留（不删报告、不删页面），新达到任一条件的加进来；同步复核 turtle-turtle.com 公司页并更新 `top-holdings.json` 的外链字段；更新 `analysis/*.md` 与 `stock-verdicts.json`；站内写死的旧研究截止日一并改掉。
- **长赢**：用新一轮 turtle 结论 + 新 PCF 快照 + 最新已披露仓位，按 `fund-grades-rubric.md` 锁定的口径重评 18 只（不许事后改口径），更新 `fund-grades.json`（cutoff 改成新截止日）与站内评价截止日。
- **推送与汇报**：本地构建通过后推仓库并验证 CI 部署全绿；每次推送需人工点一次批准；汇报重点是结论翻转的股票（通过↔未通过）和评级翻转的基金（A/B/C 变化），无翻转也如实说一句。

## 按持仓股票看（名单里的 62 只）

`/stocks` 总览 + `/stocks/<代码>` 每只独立分析页（报告原文在 `analysis/`，每只股票一个 md 文件）：
每只列出持有它的基金与占各基金 PCF 篮子的权重，并用龟龟方法（V5.2.2，先判断经营、再判断价格，六年现金回本）做一遍分析。
银行/保险不适用现金回本法，改用 ROE / 分红 / 资产质量 / 资本框架判断。
基金详情页的 PCF 表里也有一列“价格条件”，分析过的股票直接显示通过/未通过并链到它的独立分析页。
62 只中 15 只在赛博龟龟陪审团站内有收录报告（页面挂了外链），其余 47 只该站没有页面。
`/stocks` 总览表最后一列是龟龟陪审团外链（“几份报告 →”或“—”）；基金详情页 PCF 表的价格条件列里，分析链接后面也跟了同样的外链（18 只详情页共 52 处）。
结论（研究截止日 2026-11-24，股价为 11-23 收盘）：62 只里 15 只价格条件通过，全部是金融（12 家银行、中国平安、中信证券、国泰海通）；其余 47 只未通过，非金融里最接近通过的是格力电器（Coverage(6) 0.90）。
